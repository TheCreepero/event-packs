# Source format of a pack

Everything a pack ships, except its `descriptor.mod` and `thumbnail.png`, is generated by `build.ps1 -Generate` from `source/<pack>/`. This page describes those files. `build.ps1 -Check` enforces every rule here, and `build.ps1 -Check -Plan <plan>` the same rules on a plan's blocks before they are written (section "Plans").

## `events.json`

```json
{
    "pack": "finland",
    "tag": "FIN",
    "namespace": "ep_fin",
    "displayName": "Finland",
    "events": [
        {
            "id": 1,
            "key": "isthmus_volunteers",
            "title": "Volunteers on the Isthmus",
            "desc": "First paragraph.\n\nSecond paragraph.",
            "picture": "abatis",
            "factSheet": "isthmus_volunteers",
            "anchors": ["Karelian Isthmus", "Taipale", "Summa"],
            "fire": { "after": "1937.5.1", "before": "1937.9.1", "chance": 10, "trigger": "has_war = no" },
            "options": [
                { "name": "Every metre counts.", "ai": 70, "effects": [ { "war_support": 0.02 }, { "timed_idea": "volunteer_work", "days": 120 } ] },
                { "name": "Send them home before the harvest.", "ai": 30, "effects": [ { "political_power": 25 } ] }
            ]
        }
    ],
    "ideas": [
        { "key": "volunteer_work", "name": "Volunteer Work on the Isthmus", "desc": "...", "picture": "generic_morale_bonus", "modifier": { "war_support_factor": 0.03 } }
    ]
}
```

| Field | Rule |
|---|---|
| `namespace` | `ep_` and the tag in lower case. Never changes after a release: saves hold the guard flags `ep_<tag>_fired_<id>`. |
| `factQuotesFromId` | Optional, a whole number from 1. The fact-sheet sections of events with a lower id may lack quotes: they were planned before facts were quoted. Absent, every event needs them. An audit that quotes those facts removes the field. |
| `id` | Whole number from 1, unique in the pack, never reused or renumbered after a release. The event is `<namespace>.<id>`. |
| `key` | Lower-case letters, digits, underscores; names the fact-sheet section by default. |
| `title`, `desc`, option `name` | English, plain ASCII punctuation, no double quotes (use single quotes), and none of the characters the localisation reads as markup: square brackets [LOC-004] [LOC-006], the section and pound signs [LOC-009], the hash sign, and the dollar sign (a lone one is harmless [LOC-015]; it is refused to keep the texts plain). `desc` 40 to 170 words, at most 2,226 characters [GUW-046]; `\n\n` between paragraphs. The text rules are in `docs/style-guide.md`. |
| `anchors` | At least two names, places, dates or figures from the fact sheet; at least two must appear in `desc` word for word. |
| `picture` | A key of `pictures.json`, or `vanilla:GFX_report_event_<name>` for a picture of the base game [SPR-028]. |
| `fire.after`, `fire.before` | `YYYY.M.D`; the event can fire only between them [SCR-091]. |
| `fire.chance` | Percent per week, 1 to 100 [SCR-089]. 5 to 15 spreads an event over a few months; 100 fires it in the first week. |
| `fire.trigger` | Optional Clausewitz trigger lines, checked in the country's scope every week. Only the pack's own flags and vanilla triggers: never another pack's names. A war event, or an event about preparing for a war, gates on the game state here, not on `fire.after` and `fire.before` alone: the war does not start on its historical date, so its window is wide and its text names no date for the war or the preparations. A peacetime event adds `has_war = no`. |
| `ai` | The option's `ai_chance` factor: an AI-controlled country also gets the pack's events and picks an option by these weights [SCR-093]. |
| `effects` | A list of one-key objects, each at most its cap in `data/effect-caps.json`, either way: `stability`, `war_support` (shares of one [SCR-088]), `political_power`, `army_experience`, `navy_experience`, `air_experience`, `command_power`, `manpower` (the experience and manpower in whole numbers), `popularity` with `ideology`, one of the file's `ideologies` (a share of one [SCR-104]), and `timed_idea` with `days` (at most `ideaMaxDays`) [SCR-090]. |
| `ideas` | Timed ideas only; `picture` from `data/effect-caps.json`; one to three modifiers from the list and caps there. Name and description follow the text rules. |

## `pictures.json`

Written only by `build.ps1 -FetchPicture`, and by `build.ps1 -RemovePicture -Pack <pack> -Key <key> [-DryRun]`, which drops a row no event uses together with its cached download. `-FetchPicture` reads the licence from the Wikimedia Commons API through the Manager's shared licence gate (`tools/HoiImageSources.ps1`, a synced copy shared with Leader Packs; never edit it here), called with this mod's policy: Commons only, no CC BY-SA. It refuses anything but public domain (with a `PD-` template stating why), CC0 or CC BY (with a named author), own work (`PD-self`, `{{Own}}`, `{{Self}}` or an "Own work" credit) on a picture dated before 1960 (by its date, or failing that the first year in its name, description or title), a file tagged for deletion or dispute, a file that is not a picture, a download outside Wikimedia's servers, and a picture smaller than 210x176. `build.ps1 -Check` fails on a used own-work row dated before 1960 and warns on a used own-work row without a date; it derives the licence category from the recorded Commons code again, requires the Commons page and download URLs, the hash and the fetch date, and compares the hash with the cached download; `-Audit` warns about a licence read more than 180 days ago. Fetching a picture again keeps its crop and tone unless new ones are given. A Commons request that Wikimedia answers with 429 or 503, in `-FetchPicture` or in the download of a picture missing from the cache, is tried again up to five times in all, waiting 5, 10, 20 and 40 seconds, or longer when its `Retry-After` asks (at most 120), and prints Wikimedia's own message each time. The User-Agent names the repository as its contact, as Wikimedia's User-Agent policy asks. Each row keeps the Commons title and page, the download URL and its SHA-256, author, credit, licence, licence URL, Commons restrictions, the original date and size, the crop (`0` to `100`, `50` centres; or `fit`), the tone (`none`, `grey`, `warm`) and the date it was fetched. To change a crop or tone, fetch the picture again with the new values.

## `fact-sheets.md`

One section per event, headed `## <key>`, with the facts the text may use, one per line, each checked on its page by `ep-audit-researcher`:

```markdown
- <fact>. Source: <URL> (<page title>). Quote: «<the line of the page that states it, in its language>»
```

The event's text may use nothing else; the editor cuts what is not here and judges each claim against the quote. `-Check` fails on a fact line without its source and quote in the section of an event at or above `factQuotesFromId`, and on a fact marked `UNVERIFIED` in any section: only facts read on their page belong here. `-Audit` warns while a pack has events below `factQuotesFromId`.

## `research/<pack>/<YYYY-MM-DD>-dossier.md`

The historical researcher's dossiers, one per research run (parallel runs of one day write `-2`, `-3` and up), kept with the repository and never deleted or trimmed: one `## <key>` section per candidate event with its date, kind, suggested window, quoted or `UNVERIFIED` facts, anchors, the government's choice and picture ideas. A section whose event went into a READY plan carries a `Used: <plan file name>` line under its heading; the others are the candidates a later expansion of the pack starts from. Every check of a candidate's facts on their pages (Phase 3a of `event-pack-create`, Phase 1 of `event-pack-audit`) adds a line below that: `Checked: <plan file name>, <K> kept, <F> fixed, <D> dropped. The facts below are the researcher's notes, not the checked ones: see <where>.` `<where>` is `source/<pack>/fact-sheets.md` for a candidate that became an event, and `the plan's "Fact verification"` for one replaced after the check. A later check adds its own line below the earlier ones; no line is ever edited, and the newest one counts. These two kinds of line are the only changes a dossier ever gets. Nothing reads these files at build time, and nothing in them ships.

## `workshop-intro.bbcode`

The opening of the pack's Workshop description in Steam BBCode. `-Generate` adds the event list, a short picture credit with the licences (no link to the wiki: the Workshop page carries no Wiki or GitHub links), and, after it, the cross-link block between the `<!-- cross-links:begin -->` and `<!-- cross-links:end -->` lines. The block is the Manager's, not this repository's: `Scripts/Workshop/Sync-WorkshopCrossLinks.ps1` of the Modding Manager writes it into each pack's description, and `-Generate` carries what is between the markers over unchanged.

## The bundle: `source/all/workshop-intro.bbcode`

The bundle "Immersive Events Expanded" is the package `all` in `tools/HoiModBuild.json`, with a `members` list of every pack (`-NewPack` adds a new pack to it). `packs/all/` holds only `descriptor.mod` (hand-written: name, the tags of its packs, `version="1.0"`, the `supported_version` of its members), `thumbnail.png` and the generated description; the events, ideas, pictures and localisation come from the members when the item is built, so nothing is committed twice. `source/all/workshop-intro.bbcode` is its one hand-written source: the hero region, a first sentence that names every member's country (`-Check` fails for one it leaves out) and the period, and the Info section with `<!-- region:info:checksum-event-pack,bundle-choice,small-effects,game-version -->`. `-Generate` (also when a pack is generated) appends a `[h1]Countries[/h1]` list with each member's display name and event count, and the cross-link block, to the bundle's `WORKSHOP_DESCRIPTION_GUIDELINES.md`. `build.ps1 -Check` also fails for a pack that is not a member, a `supported_version` that differs from a member's, a bundle page that differs from what the source generates, and a file in `packs/all/` other than the three.

## Plans: `-Check -Plan` and `-ApplyPlan`

A plan in `docs/plans/` carries the source it writes: a ```` ```json events ```` block, a ```` ```markdown fact-sheets ```` block (`## <key>` sections) and the rows of its "Pictures" table. The pack is the plan's `Pack: <key>` line or the block's `"pack"` (`-Pack <key>` when it names none; all three must agree).

- `build.ps1 -Check -Plan <plan> [-Pack <key>]` runs the source checks of this page on what the source would be after the plan, before anything is written: the events block merged over `source/<pack>/events.json` as below, the fact-sheet sections put over `fact-sheets.md`, and the "Pictures" rows counted as pictures of the pack. A picture row not fetched yet is checked for what the table shows: the key, a `File:` name, a licence that starts with `PD`, `CC0` or `CC BY` (not `CC BY-SA`) as the dry run printed it, a size of at least 210x176 when the row gives one, the crop and the tone; a row no event uses, and a fact-sheet section of the block no event uses, are warnings. It ends `Plan check OK` or `Plan check FAILED`, and writes nothing.
- `build.ps1 -ApplyPlan -Plan <plan> [-Pack <key>] [-DryRun]` runs the same check, writes nothing if it finds an error (`ApplyPlan refused`), and otherwise writes `source/<pack>/events.json` and `fact-sheets.md`, printing each event, idea and section it changes or adds and ending `Applied <plan>` (with `-DryRun`, `Dry run: <n> file(s) would be written` and nothing written; `0 file(s)` means the source already holds the plan's blocks). `events.json` is written in the format of every pack's file (four-space indents, one item per line, the text's own characters, UTF-8 without BOM, the line ends the file had); `fact-sheets.md` keeps every line outside the sections it replaces.

The events block takes one of two forms:
- **The whole file** (a new pack, new events): the block is `events.json` as it will be. It must hold every event the file holds now, since an event id is never removed.
- **The changed events only** (an audit): `"mergeById": true` at the top, beside `"pack"` and `"tag"` (both required; `"namespace"` and `"displayName"` may be there and must equal the file's), and `"events"` with only the events that change, each as its whole object. Each takes the place of the event of the same `id`; the other events and their order stay as they are. An `id` the file does not hold is refused: a new event goes into a whole block. `"ideas"` works the same way by `key`, a new key being added at the end; `"factQuotesFromId"` sets that field, and `null` removes it. No other field is allowed. A block event replaces the whole event, so it carries every field it keeps: a field its current event has and it lacks is dropped, with a `[WARN]`. A merge cannot remove an idea (a whole block can), and `-ApplyPlan` never removes a fact-sheet section (a plan step of its own does).

## Generated files

| File | From |
|---|---|
| `packs/<pack>/events/ep_<tag>_events.txt` | the events; every one `is_triggered_only` |
| `packs/<pack>/common/on_actions/ep_<tag>_on_actions.txt` | one `on_weekly_<TAG>` anchor per event: guard flag, dates, trigger, weekly chance [SCR-080] [LOAD-011] |
| `packs/<pack>/common/ideas/ep_<tag>_ideas.txt` | the ideas |
| `packs/<pack>/interface/ep_<tag>_event_pictures.gfx` | one sprite per picture used |
| `packs/<pack>/gfx/event_pictures/ep_<tag>/*.dds` | `build.ps1 -ConvertPictures`: 210x176 uncompressed DDS |
| `packs/<pack>/localisation/<language>/ep_<tag>_l_<language>.yml` | the English text in all ten languages [LOC-017], UTF-8 with BOM [LOC-001] |
| `packs/<pack>/WORKSHOP_DESCRIPTION_GUIDELINES.md` | intro, event list, the licences in one sentence, other mods |
| `packs/all/WORKSHOP_DESCRIPTION_GUIDELINES.md` | the bundle's intro, the country list with event counts, other mods |
| `wiki/Event-Pack-<Country>.md` | event table with each picture's source, licence (CC BY linked) and author: the full credits; the Workshop description has a short credit with the licences and no link to the page |

Nothing else may sit in `packs/<pack>/`: `-Check` fails on any file there that is not `descriptor.mod`, `thumbnail.png`, a generated file or the picture of a used manifest row, so nothing ships unchecked. `build.ps1 -PreviewPictures -Pack <pack>` writes PNG copies of the pictures to `scratch/preview/<pack>/` for a look at the crops. `build.ps1 -RenderEvents -Pack <pack>` draws each event as the game's event window, and `00-overview` with several on a pile, into `artifacts/workshop-images/<pack>/`, outside the pack, for the Workshop page, plus `contact-sheet-NOT-FOR-WORKSHOP` (every event as a small card under its file stem on one image, for the agent's check of the renders; never uploaded).
