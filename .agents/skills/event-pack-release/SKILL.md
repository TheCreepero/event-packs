# Event Pack: release a pack

Each pack is a Workshop item of its own, and the bundle "Immersive Events Expanded" (package `all`) holds all of them. The agent cannot load the shared `hoi4-mod-release` skill: first ask the owner to run `/hoi4-mod-release` in this session, and do not read its file instead. Once the owner has run it, work from both skills: follow its sections "Repos with packages" and "A pack that belongs to a bundle", with these additions. Every command names the package: `-Pack <key>`, or `-Pack all` for the bundle alone.

A pack's release is one run with two items: the pack goes up first and the bundle next (with the released members and this pack). Until the bundle has a `remote_file_id` in `packs/all/descriptor.mod`, only the pack goes up and the preflight shows `Bundle: Upload WARN skipped: bundle 'all' not yet published`; the bundle's own first release is section 6.

## 0. Release waves
A new country ships its Event Pack and its Commanders Pack in the same session, so the bundles of both families are touched close together (the plan assumes Steam's trend sort rewards a week of activity; this is not checked). Release the Event Pack here and the Commanders Pack through `leader-pack-release` one after the other, not days apart. Each change note names the events of the pack; `Publish-Mod.ps1` puts the country in front of it for the bundle, so the owner types the note without the country. The owner's launch posts link the two bundles and the collection rather than the single packs; draft the text on request.

## 1. Preflight
1. `powershell -NoProfile -File "<Manager root>\Scripts\Publish-Mod.ps1" "Event Packs" -Pack <key> -PreflightOnly`. Done when no row is FAIL, the `Bundle:` rows included. A FAIL `Bundle: Unreleased member changes` names another member with committed changes since its own `workshop-<member>-` tag: release that member first, or wait, so the bundle and every single pack stay the same release.
2. `powershell -File .\build.ps1 -Audit -Pack <key>`: no `[ERROR]`. A `[WARN]` that a picture's licence was last read over 180 days ago: fetch it again for real, `powershell -File .\build.ps1 -FetchPicture -Pack <key> -File "<its commonsTitle>" -Key <its key>` (it keeps the recorded crop and tone), then `-ConvertPictures` and `-Generate`, and commit before the release; a `REJECTED` stops the release.
3. `powershell -NoProfile -File "<Manager root>\Scripts\Knowledge\Test-HoiKnowledge.ps1" -Repo event-packs -Detailed` (the `hoi4-modding-knowledge` skill): no blocking finding, and none of the files this release changed is in the sweep queue (a queue left by other work is only a WARN of the preflight).
4. Any picture whose Commons page lists restrictions (the audit prints them as `[WARN]`): the owner has looked at it and agreed.

## 2. In-game check
1. `powershell -File .\build.ps1 -DevLink -Pack <key>`, and `powershell -File .\build.ps1 -TestMod -Pack <key>` for the console commands. The test mod is the dev-only tool for the console commands; the real bundle item is `powershell -File .\build.ps1 -DevLink -Pack all` (the bundle and a single pack of the same release load together without a duplicate [LOAD-022]; a pack of another release beside the bundle has not been checked).
2. Ask the owner to start a game as the pack's country with only this pack and "Event Packs Test (dev only)" enabled (plus their usual playset if they want), and to run `event ep_<tag>.<id>` in the console for each new or changed event, or `ep_<tag>_all` for every event: picture, title, text and options as planned, effects as the tooltip shows them. The test mod is never part of the upload.
3. Read `Documents\Paradox Interactive\Hearts of Iron IV\logs\error.log` for lines naming `ep_<tag>` or the pack's files. Done when the owner reports what they saw and the log has no such line.

## 3. Change note and credits
1. The change note names the events added or changed, by title.
2. The picture credits are on the pack's wiki page (`wiki/Event-Pack-<Country>.md`, generated), which the Workshop description does not link to (it carries no Wiki or GitHub links): run `powershell -File .\wiki\push-wiki.ps1` before the upload, so the page is live and complete. A first upload, or a `WORKSHOP_DESCRIPTION_GUIDELINES.md` changed since the pack's last tag (the latest of `git tag --list "workshop-<key>-*"`, a same-day release has `-2`, `-3`; `git diff <tag>..HEAD --stat -- packs/<key>/WORKSHOP_DESCRIPTION_GUIDELINES.md`), takes `-UpdateDescription`, so the description on Steam is the generated one.

3. A first upload also needs the page's images: the preflight's Workshop text row fails while the `hero` or `overview` of the pack has no address in the Manager's `Config/workshop-image-urls.json` (`event-pack-<country>/hero` and `/overview`). Render them with `powershell -NoProfile -File "<Manager root>\Scripts\Showcase\Export-HoiDescriptionImages.ps1" "Event Packs" -MissingOnly`, show them to the owner, let them upload to Imgur and give the addresses, add them to that file, then run the Manager's `Sync-WorkshopRegions.ps1` and `Sync-WorkshopCrossLinks.ps1` (the cross-link block carries the series banner) with `"Event Packs"`, and commit on the owner's word.

## 4. Upload and tag
1. `Publish-Mod.ps1 "Event Packs" -Pack <key> -DryRun -ChangeNote "<note>"`: show the owner both VDFs (a dry run exits 0 even with a FAIL row in the table above it, so it counts only after the preflight shows none). The pack's: title `Event Pack: <Country>` and the file list (only that pack's content, descriptor and thumbnail). The bundle's (once it is published): title `Immersive Events Expanded`, the change note `<Country>: <note>` and the file list (the released members' content plus its own descriptor and thumbnail).
2. Give the owner the upload command for their own terminal: `powershell -NoProfile -File "<Manager root>\Scripts\Publish-Mod.ps1" "Event Packs" -Pack <key> -ChangeNote "<note>"`, with `-UpdateDescription` per step 3.2. The same run uploads the bundle; its description goes up when its text changed since its last tag, whatever `-UpdateDescription` says.
3. A first upload writes the new id into `packs/<key>/descriptor.mod`: ask the owner to commit it. The command tags `workshop-<key>-<date>` and, for the bundle, `workshop-all-<date>`; pushing the tags is the owner's call. If the bundle's upload fails after the pack's went up, the run exits 1, says which item went up and prints the command that uploads the bundle alone (`-Pack all`).
4. `Test-ModWorkshopListing.ps1` (the Manager's) shows OK for the pack and for the bundle.
5. A new pack's first upload (no `remote_file_id` before the run) is a wave, not one command: its new id is missing from the "More from the author" list of the other published packs and of its own page (its first upload carried a list without itself) until they are uploaded again. The preflight says so before the run (a `Pages stale after upload` WARN row, the steps under its table, printed again after the upload); the bundle's page is not affected. Carry it out in the same session: (a) the owner commits `packs/<key>/descriptor.mod`; (b) run `powershell -NoProfile -File "<Manager root>\Scripts\Workshop\Sync-WorkshopCrossLinks.ps1" "Event Packs"` and commit the pages it changed on the owner's word; (c) give the owner one `Publish-Mod.ps1 "Event Packs" -Pack <key> -SkipBundle -UpdateDescription -ChangeNote "Description refresh"` per page the preflight listed, the new pack included (such an upload adds no entry to the Workshop change notes [WS-007]); (d) `Sync-WorkshopCrossLinks.ps1 -Check` (no mod name) says Current; it reads the files, so the wave is done when every command of (c) has run.
6. Remind the owner to add the new pack's item to the Steam collection "The Immersive Series: Event Packs" (collection 3834986983) by hand; the bundle stays out of it, it belongs to the main collection. The collection text and its banner then name the pack: `Test-WorkshopText.ps1 -Collection event-packs` fails until the Manager's `docs/workshop-collection-event-packs.bbcode` links it, and `Export-HoiBrandingShowcase.ps1` redraws the banner (the Manager's `hoi4-workshop-description` skill).

## 5. Event images on the Workshop page
SteamCMD uploads only the thumbnail, so the event images go up by hand.
1. `powershell -File .\build.ps1 -RenderEvents -Pack <key>`, from the committed pack: one image per event in `artifacts/workshop-images/<key>/`, named `NN-<event key>` (the id in two digits), and `00-overview` with several events on a pile, which comes first; every image carries the country's flag at the top right. No `[ERROR]`, and no `[WARN]` outside the "Kept on judgment" of the plan that made the events.
2. Give the owner the folder's full path and these steps: on the item's Workshop page, "Add/edit images & videos"; on an update where events or their texts changed, remove the old event images first; upload the files in name order, so the gallery follows the events' order. The bundle page has no event images of its own. Its gallery is the folder `<Manager root>\Artifacts\bundle-gallery\Immersive Events Expanded\` (git-ignored, filled by hand: no script writes it), named in upload order: `01-cover.png` is a copy of `<Manager root>\Artifacts\branding\immersive-events-expanded-cover.png` (drawn by `Export-HoiBrandingShowcase.ps1`), then `02-<country>-overview.jpg`, one per member in alphabetical country order, each a copy of `artifacts/workshop-images/<key>/00-overview.jpg` of this repository. When a member joins or its overview changes, copy the file in (a new country renumbers the files after it), give the owner the folder's full path and have them replace the bundle's gallery the same way: remove the old images, upload in name order.

## 6. The bundle's first release
Only on the owner's word, and only after the in-game check of the bundle (plan `2026-11-06-workshop-visibility-bundles`, Item 1 step 7) is recorded; it is, for the same-release loads [LOAD-022]. The check of a pack of another release beside the bundle waits for the next real pack release and does not gate the first upload.
1. `powershell -NoProfile -File "<Manager root>\Scripts\Publish-Mod.ps1" "Event Packs" -Pack all -PreflightOnly`, then `-DryRun -ChangeNote "<note>"`; show the owner the VDF and the file list. Until step 2 is done the Workshop text row is FAIL for the missing images, which is expected. The bundle ships the released members only.
2. The page's images first: the preflight's Workshop text row fails while the bundle's `hero`, `strip-info` or `strip-countries` has no address in the Manager's `Config/workshop-image-urls.json` (`immersive-events-expanded/hero`, `event-bundle/strip-info`, `event-bundle/strip-countries`); render them as in section 3 step 3 with `-Pack all`, and the owner uploads them. The same row fails while the page lacks its cross-link block: `Sync-WorkshopCrossLinks.ps1 "Event Packs"` writes it into the bundle page before the id exists (it is covered only when the mod is named), and commit.
3. The owner runs the first upload with `-UpdateDescription` in their own terminal. It writes the new id into `packs/all/descriptor.mod`: ask the owner to commit it.
4. `powershell -NoProfile -File "<Manager root>\Scripts\Set-ModWorkshopTags.ps1" "Event Packs" -Pack all` sets the tags [WS-001] (the Manager's script, the owner's Steam client running); the owner makes the item public.
5. Then `Sync-WorkshopCrossLinks.ps1` for every page names the bundle, the single packs' text gains its link line, the collection text puts the bundle first (the Manager's `hoi4-workshop-description` skill), and the owner adds the bundle to the collection.
